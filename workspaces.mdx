在 AGW 中，每个 `Project.Workspace` 都必须是 **AGW Server 进程可见的目录**。文件 API、Git 操作、Claude Code 与 Codex 使用**同一棵本地工作树**，这确保了外部 Agent 看到的文件状态与 AGW 中呈现的一致。

## 目录可见性

`Project.Workspace` 必须由 AGW Server 进程直接访问：

- **本地目录**：填写绝对路径。
- **网络存储**：需要先通过操作系统或容器平台完成挂载，再把挂载路径配置为 Workspace。

<Warning>
AGW **不提供**应用内 SFTP 或类似的远程文件后端。远程存储必须先在系统层挂载。
</Warning>

## Chat Workspace Files

Chat 提供两种 Workspace 文件视图：

- **All Files**：Workspace 中的完整文件树。
- **Git Changed Files**：仅显示 Git 检测到的变更文件与 diff。

这两个视图与本地工作树实时同步，因此可以在 Chat 中直接跟踪 Agent 对文件的修改。

## 修改 Workspace 后需要重启

<Note>
已经使用过的 Workspace 发生变化后（例如把根目录改到另一个路径），需要**重启 AGW Server**，以确保所有缓存与 Git 状态被重新加载。
</Note>

## 外部 Agent 的 Model Provider 关系

Claude Code、Codex 与 Pi 都可以在 Agent 定义中选择 Model Provider：

| 外部 Agent | 支持的 Provider |
| --- | --- |
| Claude Code | Anthropic |
| Codex | OpenAI Responses |
| Pi | 全部三种 ProviderType |

取消选择后，该外部 Agent 会沿用其自身的 CLI 配置。Agent 定义的修改在**下一轮生效**并保留当前会话。

## 权限模式

Chat 只提供目标外部 Agent 支持的权限模式：

- **Claude Code**：多种权限模式，见 [Claude Code SDK 工具权限](/sdks/claude-code/configuration/permissions)。
- **Codex**：仅 Full access。
- **Pi**：仅 Full access。
